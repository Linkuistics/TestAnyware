# lifecycle-evidence-k8


## Goal

Specify the smallest coherent supported command lifecycle and evidence-transfer
contract from the causal findings, including compatibility and validation.



## Context

- Read the eight causal `docs/experiments/exec-reliability-*.md` reports from
  `macos-completion-k3`, `macos-timeout-inspection-k4`,
  `macos-exec-outcomes-k12`, `macos-disconnect-availability-k13`,
  `linux-timeout-lifecycle-k5`, `linux-disconnect-availability-k6`,
  `download-consistency-k7` and `linux-download-consistency-k14`, including
  their raw evidence and test invocations. Read k11's diagnostic-foundation
  report for the controller, routes and unavailable prerequisites.
- Read affected current protocol types and exact dependencies; reconcile public
  help/schema with `agent-protocol.md` and `cli-design-contract.md`.
- The root's agreed seams, acceptance inventory/bounds, ten-clone trial,
  isolation and continuation obligations remain authoritative.

## Done when

- Classify causal findings as established, non-reproduced, unavailable or
  unresolved. Keep the two macOS symptoms separate unless evidence connects
  them. Insert a precise investigation before this live leaf if a missing fact
  is load-bearing; never invent a repair premise to finish the design.
- Record a durable spec and minimum coherent ADR set for typed guest terminal
  outcomes (numeric exit including 23, timeout, cancellation, signal, spawn
  error), separate transport failures and exact/partial evidence. Define start,
  terminal arbitration at exit/deadline/cancel races, cancellation idempotence
  and evidence availability/retention.
- Choose explicit cancellation independently from abrupt CLI disconnect policy.
  Define stopping new work, process ownership/group scope and identity checks,
  grace <=2 s then kill/drain/reap <=2 s, responsive independent requests and
  escaped-descendant limits. Controller/VM disposal cannot replace the production
  execution owner or make a blocked channel acceptable.
- State mutable-file consistency or an explicit exclusion plus the tested stable
  alternative; specify incomplete/contradictory evidence and host finalization
  errors. Preserve bounded-memory streaming or reconcile ADR-0001 with evidence.
- Specify text/JSON semantics, guest status versus host transport status,
  receipts/schemas and contradictions. Preserve or deliberately version affected
  supported macOS/Linux/Windows wire shapes with a skew matrix; reconcile agents,
  shared/vendored types, Host CLI, help and documents together. Make no Windows
  reliability claim and preserve ADR-0004's app routing.
- Map guarantees to existing process/file, HTTP/Host CLI, transport and app
  seams, old-fail/corrected-pass controls and concrete Taskfile checks. Describe
  working implementation candidates without splitting a schema from its only
  useful reader; a later planner makes the leaf cuts from the reviewed design.
- Specify the route through reviewed fixes, identified isolated production test
  builds, validated controller/checkers, frozen five-clone-per-OS full trial and
  durable downstream handoff/resource audit. Keep every root case, byte oracle
  and unchanged comparison ceiling; declare boot/slot/export/new phase bounds
  before measurement. Baseline and deterministic passes never replace acceptance.
- After the spec/ADR set exists, cut a concrete `planning` successor for the
  reviewed contract's implementation increments and later preparation, full
  acceptance and handoff/resource audit. Its body names this producer and the
  artifacts; it must read the intervening review and any reconciliation before
  relying on them. Then insert a specific `review-design` ahead of that live
  successor as the last producer act. Ask it to challenge causal premises,
  races/ownership bounds, evidence consistency, compatibility and acceptance
  feasibility. A clean review cuts nothing. Findings insert reconciliation
  before planning; substantial redesign gets its own producer/review chain
  before dependent planning. Do not rely on a reviewer to create continuation.

## Notes

Durable jobs/leases, pooling, placement and replacement backends remain outside
issue #14. Do not repeat the requirements interview. Escalate only a newly
exposed material owner trade-off with a recommendation and evidence. This leaf
produces design and review handoff, not implementation or acceptance. Decompose
if needed at a coherent contract boundary and do only the first child.

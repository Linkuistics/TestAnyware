## Decisions (running log)

The separate exec writer is a justified boundary: it moves blocking evidence I/O
off the sole scheduler without adding a controller thread or another workload
signal owner. Its readiness and publication bounds sit outside owned teardown;
the intent acknowledgement gates acquisition only. No additional ADR or safety
supervisor is warranted by this review.

The final publication protocol needs reconciliation before planning. The result
frame is frozen before publication finishes, although its promised fields include
publication outcome and every record's controller-computed digest. The identity
request also precedes a writer-generated storage-close file that the existing
retention verifier would reject as unlisted. These are contract findings, not
implementation fixes in this session.

The pipe conversion needs an explicit final-drain and completeness rule. A digest
of the consumed prefix cannot establish that unread bytes buffered at the final
process observation were retained. Any correction must preserve the existing
cleanup and disposal deadlines and must not wait for descendant EOF.

An integration step belongs immediately before `evidence-storage-k158`, the first
later live sibling. It shares the existing root context and needs no new node.
Its finite handoff is a reconciled design that planning can slice; the review
findings stay here so integration can accept or reject each on its evidence.

## Findings

Three material contract findings need integration before storage planning. This
review recommends retaining the separate writer architecture.

### F1 — Define the stored result's observation boundary and digest coverage

**Location:** `docs/specs/diagnostic-evidence-storage.md:99`,
`docs/specs/diagnostic-evidence-storage.md:120`, and
`docs/specs/diagnostic-evidence-storage.md:175`.

P3 sends the result before the identity request and close. Enqueue freezes its
bytes. Yet the stored result promises the publication outcome, frame
acknowledgement/failure counts and first failure. Those facts can change after
the result is sent: the writer can accept the result and then fail on identity
or close, or remain unreaped at P plus two seconds. Even a healthy run cannot put
the acknowledgement of the result itself into that already-frozen record.
The separate in-memory return can contain the terminal facts, but the design
does not distinguish its storage section from the persisted snapshot's section.

The digest promise has the same boundary problem. “For every record” needs an
explicit exclusion for the result containing the digest table, and an ownership
rule for records generated by the writer rather than sent by the controller.
The subjects-after cutoff also differs between line 100 (S + W/2) and line 184
(P); an acknowledgement arriving between them cannot change the queued result.

**Consequence:** implementations and readers must invent different meanings for
the same fields. A stored result can appear to report completed publication
despite a later storage failure, or require an unspecified self-referential
digest. This conflicts with `.grove/_BRIEF.md:30`, which rejects missing,
truncated or contradictory evidence as success.

**Smallest useful correction:** define the persisted result as a snapshot with
an explicit sequence/time cutoff and pending publication where appropriate;
distinguish it from the terminal in-memory outcome. Specify an acyclic digest
coverage set, the treatment of writer-generated records and the authority a
retained reader uses to establish completion. Set one subjects-after cutoff.
Keep all final reporting after teardown and within the existing P3 bound.

### F2 — Close the evidence file set before computing its identity

**Location:** `docs/specs/diagnostic-evidence-storage.md:101` and
`docs/specs/diagnostic-evidence-storage.md:199`;
`experiments/exec-reliability/retention.py:38`,
`experiments/exec-reliability/retention.py:46`, and
`experiments/exec-reliability/retention.py:114`.

The writer handles frames in order. The controller requests identity before
close, and the writer then writes a storage-close record on orderly close or
EOF. The identity therefore omits that later file. The current retention
contract pins every run file except the identity itself; `verify()` enumerates
the current files and rejects any unlisted file through `files_ok` at line 132.
Following the proposed order makes an otherwise healthy directory fail that
verification. Treating storage-close as an implicit exception would instead
leave a completion claim outside the stated evidence coverage.

**Smallest useful correction:** define one normal close transaction that freezes
the final file set, including the orderly-close record, before computing the
identity, then acknowledges completion and exits without further run-file
writes. State separately what a crash/EOF prefix may contain and whether it is
complete. If the retained format changes, specify the corresponding verifier
contract rather than silently exempting the late file. A healthy run must be
verifiable; a missing or changed close record must not pass as complete.

### F3 — Preserve or explicitly reject unread output at the final observation

**Location:** `docs/specs/diagnostic-evidence-storage.md:150` and
`docs/specs/diagnostic-evidence-storage.md:155`;
`experiments/exec-reliability/controller.py:845`.

The scheduler drains at most 64 KiB per stream per turn, then closes the read
ends at the call's final observation. There is no final-drain ordering or
completeness rule. A finite-output child can write and exit between the last
drain and that observation, leaving valid bytes buffered in its pipe. Closing
the read end discards them. A length and digest of the consumed prefix still
match the shortened retained file, so they cannot reveal the loss; calls
without `expected_stdout` have no independent content oracle.

This is a permitted schedule in the proposed contract, not a claimed reproduced
failure. The existing file-based path pins raw bytes after the termination
decision and reap, and explicitly treats those pins as observations. Moving to
pipes must define the corresponding stream observation boundary. The unchanged
scheduler also prioritises ready safety turns
(`experiments/exec-reliability/turns.py:73`); it supplies no implicit guarantee
that a stream turn precedes a terminal process turn.

**Smallest useful correction:** specify how already-buffered output is drained
within bounded work before freezing the stream receipt, and how a cutoff or
unknown completeness fails the affected receipt. Cover both a normal exit with
buffered output and an inherited writer that never closes. Do not wait for
descendant EOF or add a new allowance to cleanup or disposal. Receipt pins must
describe exactly the bytes whose expected-output comparison was made.

## Design assessment and evidence limits

**Supported by inspection:** the controller retains workload signal/reap
authority; the writer has its own exact-PID lifetime; no acknowledgement gates
teardown; bounded nonblocking outbox turns isolate storage backpressure. The
writer-command seam enables concrete stalls, errors and death without moving
storage into the inspection worker. An exec writer avoids the extra controller
thread forbidden by fork admission. These responsibilities earn the process
boundary. No additional interface layer or ADR is justified here.

**Accepted tradeoffs:** acknowledged writes are not durable; controller-crash
recovery and command-start hazards outside the evidence root are excluded;
an uninterruptible writer may remain a reported residual. The spec names these
limits. None supplies grounds to extend the 30-second cleanup or 45-second
disposal ceiling.

**Unresolved:** F1–F3 cover publication consistency and stream capture. They
require protocol clarification and subsequent verification, not a different
signal owner. The nine proposed fault controls are a design obligation, not
executed evidence. This review makes no new live-VM, permission or setuid-ps
claim; historical ten-clone acceptance remains 0/10, unavailable.

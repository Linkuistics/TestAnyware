# Declared worker shutdown phases (complete-worker-scheduler-k104)

`Plan` and direct `Worker` construction now accept immutable `FailureBounds(term_grace=2, kill_reap=2)` and `CloseBounds(grace=0.05, kill_reap=2)`. Every duration must be an actual int/float, positive and at most two seconds. Validation precedes Plan hashing/output creation and direct-worker admission/fork. Plan JSON and worker evidence retain all four declarations.

The [inspection contract](../../../../docs/specs/diagnostic-process-inspection.md) requires a single orderly grace followed directly by KILL/reap, or failure TERM grace followed by KILL/reap. `Worker.close` uses those declarations on one fixed timeline. EOF requests orderly shutdown; failure to close that channel selects failure shutdown on the same original clock. An unready direct child uses the failure timeline and exact PID signals. A validated session uses group signals. Existing TERM/KILL attempts, including denied attempts, suppress duplicate signals. A prior KILL anchors the reap allowance at that attempt. An earlier owner cutoff constrains both phases; reserve the declared reap allowance inside that cutoff rather than renewing grace. Expired cutoffs permit no further signal/probe entry in this slice.

The `shutdown` receipt records mode, absolute start/grace end/reap end/finish, final outcome, signals, and separate grace and kill/reap phase receipts. Each phase records its start (null when not entered), deadline, finish, outcome, exhaustion, strict overrun and nonnegative lateness. Overrun is strict `finish > deadline`; equality is exhausted but not overrun. A late callback cannot renew the cutoff. `bootstrap_shutdown` retains the same bootstrap-specific receipt via the shared implementation. Failure is sticky; close is idempotent; simulated unreapability retains the strong owner and residual remedy.
